# 依存関係

依存関係はチケット間の関係をタイムラインに線で表示します。`precedes` / `follows` はスケジュール制約として使われ、参照専用の `relates` やブロック関係とは働きが異なります。

## 手動保存 {#手動保存}

**自動保存** がオフの場合、依存関係の作成・編集・削除は下書きになります。エディターの **変更を保留** で確定し、ツールバーの **保存** でチケットの変更とまとめて保存します。自動保存がオンの場合はすぐに送信します。

- 新規・更新した関係は破線で表示され、日程の制約チェックやクリティカルパス計算にも反映されます。削除予定の関係は計算から除外されます。
- **保存** のツールチップでチケットと依存関係の件数を確認できます。
- **キャンセル** は未保存のチケット・依存関係とエディターの入力をまとめて破棄します。保存済みの変更は取り消せません。
- 保存中に変更を保留できなかった場合は、入力を残してエラーを表示します。保存完了後に再操作してください。

チケットを先に保存し、成功後に依存関係を保存します。途中で失敗すると、一部だけ保存されることがあります。残った下書きとエラーを確認してから再試行してください。

既存の先行関係を解除しないと日付を前倒しできない場合などは、一括保存できません。先に関係の変更を保存し、その後で日付を変更・保存します。

### 保存に失敗した・結果が不明な場合

権限不足や入力エラーなどで拒否された変更は **失敗** として残ります。エラーを修正してから再試行してください。

タイムアウトなどで成否がわからない変更は **不明** として残り、自動再送されません。右側の確認パネルでサーバーの状態を確認します。閉じた場合は **依存関係を確認**（チケットの競合もある場合は **競合した変更を解決**）で開き直せます。

- **適用済みにする**: サーバーに意図した変更が反映されている場合に選びます。
- **確認して再試行**: 変更が未反映で、元の状態が維持されている場合に選びます。
- **失敗した依存関係の保存を再試行**: 失敗した変更を再保存します。他の保留中の変更も保存対象になる場合があります。

確認には関係の両端のチケットが必要です。フィルターで隠れていれば両方を表示してください。状態が食い違う場合や確認できない場合は、未解決のまま Redmine で確認します。

結果不明の作成・更新は、確認が取れるまで日程計算に使われません。削除結果が不明な関係は、既存の線と日程計算を維持します。チケットの保存結果が確認できない場合も下書きを残し、確認中に行った新しい編集は保持します。

## 作成

1. 先行チケットのタスクバーの左右端付近にある依存ハンドルからドラッグします。
2. 後続チケットのタスクバー付近でドロップします。
3. ツールバーの **デフォルト依存関係を自動適用** がオフなら編集ポップオーバーが開きます。関係種別と必要な delay を選び、**保存**（自動保存オフでは **変更を保留**）を押します。オンなら、ツールバーで選択した既定種別で作成します。

編集 UI では次の 3 種類を選べます。

- **先行**: 先行チケットが完了してから後続チケットを開始する関係です。delay はこの種類だけ指定でき、0 以上の稼働日数です。
- **関連**: 参照リンクです。スケジュール制約を作りません。
- **ブロック**: 一方のチケットが他方をブロックする関係です。

保存データが逆方向の `follows` または `blocked` の場合、編集 UI はチケットの順序を反転して表示します。スケジュール計算が開始日制約に使う関係は `precedes` / `follows` です。

## 既定値と delay

delay は先行チケットと後続チケットの間隔を指定する稼働日数です。日本語表示でも画面上の表記は「delay」です。

ツールバーの依存関係設定から既定種別、自動 delay 計算、既定関係の自動適用を変更できます。自動 delay は先行側の期日（なければ開始日）と後続側の開始日から求め、後続チケットのプロジェクトカレンダーを使います。日付が不足していれば自動計算できない旨が表示されます。

## 編集と削除

1. タイムライン上の依存関係線をクリックします。
2. 開いた編集ポップオーバーで種類や delay を変更して **保存**（自動保存オフでは **変更を保留**）を選びます。
3. ポップオーバーの **削除** で関係を解除します。チケットを右クリックし、表示された関連関係の一覧から削除する方法もあります。

重複、循環依存、権限、日付整合性の制約により保存できない場合があります。編集には関係するチケットの可視性と権限が必要です。プロジェクトをまたぐ関係は Redmine の `cross_project_issue_relations` 設定に従います。

## スケジュールへの影響

自動スケジュールと依存関係検証はチケットのプロジェクトカレンダーを使います。最小開始日の判定では後続チケットのカレンダーが基準です。カレンダー設定は[営業日カレンダー](/ja/administration/calendars)を参照してください。

ツールバーの **依存関係に基づいて整理** は表示順を変える設定で、関係の作成や削除は行いません。
