# 依存関係

依存関係はチケット間の関係をタイムラインに線で表示します。`precedes` / `follows` はスケジュール制約として使われ、参照専用の `relates` やブロック関係とは働きが異なります。

## 開発版の手動保存 {#手動保存}

マニュアル対象の v0.18.0 では、自動保存がオフでも依存関係の作成・編集・削除はすぐに Redmine へ送信されます。開発版では **自動保存** がオフの場合の動作が変わります。

- 作成・編集・削除はローカルの下書きとして保留されます。依存関係エディターの主ボタンは **変更を保留** (Keep changes pending) となり、API へ送信せず変更を保持します。**デフォルト依存関係を自動適用** がオンの場合も同じです。
- 保留中の依存関係はエディターで確認でき、新規・更新された線は破線で表示されます。
- 保留中の先行関係も、現在の自動スケジュール設定に従って制約チェック・連動移動・クリティカルパス計算に反映されます。削除予定の関係は、これらのローカル計算から除外されます。
- チケットまたは依存関係の下書きがあると、ツールバーにアイコンのみのコンパクトな **保存** と **キャンセル** ボタンが表示されます。**保存** のツールチップにチケットと依存関係の件数が別々に表示されます。失敗または結果不明の依存関係変更は、レビュー通知から右側のパネルで確認できます。**キャンセル** は未保存のチケットと依存関係の変更をまとめて破棄し、依存関係エディターを閉じて入力内容も破棄します。
- **自動保存** がオンの場合、依存関係の変更は従来どおりすぐに送信されます。

保存中に別の依存関係の変更を保留しようとして受け付けられなかった場合、エラーを表示し、エディターと入力内容を保持します。**デフォルト依存関係を自動適用** がオンの場合も、作成しようとした関係がエディターに残ります。保存完了後に再操作してください。自動では再実行しません。

手動保存で権限不足・対象の不存在・競合・入力検証などの明確な拒否応答を受けた場合、依存関係の下書きは **失敗** として残ります。サーバーのエラー理由を確認し、必要な修正後に再試行してください。

一括保存は複数のサーバー要求を順に実行し、単一のデータベーストランザクションではありません。チケット変更を先に保存し、1 件でも失敗した場合は依存関係を送信せずに停止します。チケットの保存後に依存関係を再取得・再検証してから、その変更を送信します。チケットや先行する依存関係の保存が完了した後、後続の要求が失敗することがあります。保存済みの変更は維持され、未解決の依存関係変更は下書きとして残ります。部分保存の後に **キャンセル** しても、すでに保存された変更は取り消されず、残っている下書きだけが破棄されます。

依存関係の要求がタイムアウトした場合や、サーバー応答から成否を判定できない場合、結果は **不明** と表示され、自動再試行されません。右側の競合・レビュー画面は自動で開きます。閉じた後は、画面右上の **依存関係を確認** ボタンから再表示できます。チケットの競合もある場合は、共通の **競合した変更を解決** ボタンから両方を確認できます。未解決の依存関係変更がチケットの組み合わせ、操作、状態、エラーとともに 1 件ずつ表示されます。画面上に線が表示されない削除予定の依存関係も対象です。結果不明の変更を解決する前に、Canvas Gantt はサーバー上の依存関係を再取得し、意図した変更と照合します。サーバーの状態が一致する場合にのみ **適用済みにする** を選び、一致せず元の状態が維持されている場合にのみ **確認して再試行** を選びます。失敗した変更は **失敗した依存関係の保存を再試行** で再試行できます。この操作は一括保存の流れを使うため、他の保留中のチケットや依存関係の変更も対象に含まれる場合があります。再取得した状態が別の変更を示す場合や、状態を確認できない場合は未解決のままにして Redmine で確認してください。**キャンセル** は残りの下書きを破棄しますが、すでに保存された変更は取り消しません。

削除結果が不明になった関係は、確認が取れるまで画面上の関係とローカル計算に復元されます。クリティカルパス・余裕日数・依存関係順の表示も、この復元された関係に合わせて更新されます。

削除結果が不明な場合、再取得したサーバーデータに両端のチケットが含まれているときに限り、依存関係が存在しないことを削除の確認に使います。フィルターで片方でも除外されている場合は未解決のまま維持し、両方のチケットを含むようにフィルターを変更してから再確認してください。

この順序では安全に保存できない変更の組み合わせがあります。たとえば、後続チケットを前倒しするために既存の先行関係を先に削除または変更する必要がある場合、開発版はどちらも書き込む前に一括保存を拒否します。先に依存関係を保存し、その後で日付を変更して保存してください。これらの開発版の動作は v0.18.0 には含まれていません。

## 作成

1. 先行チケットのタスクバーの左右端付近にある依存ハンドルからドラッグします。
2. 後続チケットのタスクバー付近でドロップします。
3. ツールバーの **デフォルト依存関係を自動適用** がオフなら編集ポップオーバーが開きます。関係種別と必要な delay を選び、**保存** を押します。オンなら、ツールバーで選択した既定種別で作成します。

編集 UI では次の 3 種類を選べます。

- **先行**: 先行チケットが完了してから後続チケットを開始する関係です。delay はこの種類だけ指定でき、0 以上の稼働日数です。
- **関連**: 参照リンクです。スケジュール制約を作りません。
- **ブロック**: 一方のチケットが他方をブロックする関係です。

保存データが逆方向の `follows` または `blocked` の場合、編集 UI はチケットの順序を反転して表示します。スケジュール計算が開始日制約に使う関係は `precedes` / `follows` です。

## 既定値と delay

delay は先行チケットと後続チケットの間隔を指定する稼働日数です。日本語表示でも画面上の表記は「delay」です。

ツールバーの依存関係設定から既定種別、自動 delay 計算、既定関係の自動適用を変更できます。自動 delay は先行側の期日（なければ開始日）と後続側の開始日から求め、後続チケットのプロジェクトカレンダーを使います。日付が不足していれば自動計算できない旨が表示されます。

## 編集と削除

1. タイムライン上の依存関係線をクリックします。
2. 開いた編集ポップオーバーで種類や delay を変更して **保存** します。
3. ポップオーバーの **削除** で関係を解除します。チケットを右クリックし、表示された関連関係の一覧から削除する方法もあります。

重複、循環依存、権限、日付整合性の制約により保存できない場合があります。編集には関係するチケットの可視性と権限が必要です。プロジェクトをまたぐ関係は Redmine の `cross_project_issue_relations` 設定に従います。

## スケジュールへの影響

自動スケジュールと依存関係検証はチケットのプロジェクトカレンダーを使います。最小開始日の判定では後続チケットのカレンダーが基準です。カレンダー設定は[営業日カレンダー](/ja/administration/calendars)を参照してください。

ツールバーの **依存関係に基づいて整理** は表示順を変える設定で、関係の作成や削除は行いません。
