# トラブルシューティング

## Canvas Gantt メニューが表示されない

1. 対象プロジェクトの**設定 → モジュール**で Canvas Gantt が有効か確認します。
2. 利用ロールに `view_canvas_gantt` があるか確認します。詳しくは[権限設計](/ja/administration/permissions)を参照してください。
3. ログインユーザーが対象プロジェクトを閲覧できるか確認します。
4. 画面を再読み込みします。インストール直後やアップグレード後は Redmine プロセスの再起動が必要です。

<a id="issue-を編集・作成・削除できない"></a>

## チケットを編集・作成・削除できない

Canvas Gantt の表示権限だけではチケット操作は許可されません。対象プロジェクトの標準権限とチケットの可視性を確認してください。必要な権限は[権限設計](/ja/administration/permissions)にまとめています。

## 日付変更が保存されない

- 自動保存が無効なら、変更後に保存操作を行います。保留中の変更は保存前に画面を離れないでください。
- 変更対象チケットの編集権限、検証エラー、Redmine からの通知を確認します。権限は[権限設計](/ja/administration/permissions)を参照してください。
- 開発版で「最新のチケット情報を再取得できませんでした」と表示された場合、保存が確認された変更は保持されています。最新状態を再取得できるようになってから、保留中の依存関係の変更を確認して保存します。保存が確認された日付変更を再度入力する必要はありません。
- カレンダーが設定されている場合、非稼働日を選ぶと開始日は次の稼働日、期日は直前の稼働日に補正されることがあります。
- 非稼働日の「今日」を開始日に設定すると、次の稼働日へ補正されることがあります。その後、期日にも「今日」を指定すると、設定済みの開始日より前になるためエラーになります。一覧の開始日を確認し、それ以降の期日を選んでください。非稼働日そのものへ配置したい場合は、日付配置を「カレンダー日へ自由に配置」に変更します。
- 競合パネルにチケットが表示される場合は、次の節の手順で差分を確認します。

## 保存競合が発生した

別のユーザーや画面が先にチケットを更新すると、同じ日付変更グループ全体は適用されず、ローカルの下書きは保持されます。次の手順で競合を解決します。

1. 競合パネルで対象チケットごとにサーバー側またはローカルの日付を選び、依存関係と親子関係を含むグループ全体を確認します。
2. **このグループを適用** (Apply this group) を選び、操作を検証して適用します。

- Redmine のコールバックが日付を調整する場合は、影響を受けるチケットを確認してから **調整後の日付を承認して適用** (Accept adjusted dates and apply) を明示して再試行します。
- 確認した関連、delay、階層、営業日カレンダーが変わった場合は、**比較を更新して再選択** (Refresh comparison and reselect) を選び、更新後の内容を確認して日付を選び直します。
- 営業日カレンダーの revision が古い場合、画面は最新カレンダーを再取得して一度だけ再試行します。競合が続く場合は、未保存の変更が残っていないことを確認してからページを再読み込みし、最新のカレンダーとチケットを読み込んでください。

適用に失敗した場合、選択とローカルの下書きは保持されます。自動保存と手動保存で解決方法は共通です。

## 依存関係を追加できない

- 関連するチケットが表示可能で、編集可能か確認します。別プロジェクト間では Redmine の `cross_project_issue_relations` 設定も確認します。
- 循環を作る関係は追加できません。
- 先行関係と delay の日付整合性、依存先プロジェクトの営業日カレンダーを確認します。
- カレンダー設定が不正な場合は Redmine ログと[カレンダー設定](/ja/administration/calendars)を確認します。

## フィルター結果が想定と違う

ステータス、担当者、プロジェクト、バージョン、トラッカー、並べ替えなどを使う保存済み Redmine クエリと URL 条件を確認し、不要な条件を解除します。件名フィルターやワークロードのフォーカス条件はブラウザー内の個人状態で、共有 URL / 保存済みクエリと同じ条件ではありません。プロジェクトツリー外の候補チケットは明示的なプロジェクト選択が必要な場合があります。

## チャートが空、崩れる、または古い表示のまま

- フィルターを解除し、**今日**やズーム操作でタイムライン位置を戻します。
- ブラウザーがサポート対象の最新 Chrome、Edge、Firefox、Safari であること、JavaScript と `localStorage` が有効なことを確認します。モバイルブラウザーと埋め込み WebView はテスト対象外です。
- `CANVAS_GANTT_USE_VITE_DEV_SERVER=1` が本番 Redmine に設定されていないか確認します。この設定を使う場合は開発用 Vite サーバーも必要です。
- ブラウザー開発者ツールのネットワーク / コンソールでデータ要求の失敗を確認します。大きすぎる完全データ応答は HTTP 413 になります。必要に応じてフィルターを絞り込みます。
- アセット更新後は Redmine を再起動し、ページを強制再読み込みします。

## 他プラグインが操作 UI に干渉する

`redmica_ui_extension` の Select2 拡張が選択 UI に干渉する場合、**管理 → プラグイン → Redmica UI Extension → 設定**で検索可能セレクトボックスを無効にして再確認します。原因を切り分けるときは、対象プラグインの設定を記録し、変更を一つずつ戻して比較します。

## よくある質問

### プラグイン設定ページが見つかりません

Canvas Gantt には一般設定ページがありません。表示設定は Gantt 画面で変更します。詳しくは[表示とエクスポート](/ja/features/display-export)、営業日カレンダーは[営業日カレンダー](/ja/administration/calendars)を参照してください。

### カレンダーを変更したのに反映されません

ファイルの配置先と Redmine プロセスの権限を確認します。変更確認は既定で最大 60 秒間隔です。検知後に Gantt を再読み込みしてください。不正な変更は前回正常なカレンダーを維持します。

<a id="baseline-が見えない、または保存できません"></a>

### ベースラインが見えない、または保存できません

閲覧には `view_canvas_gantt`、保存には `manage_canvas_gantt_baseline` が必要です。ベースラインはプロジェクトごとに 1 件で、新しく保存すると置き換わります。詳しくは[権限設計](/ja/administration/permissions)を参照してください。

## GitHub Issue を報告する

再現手順、期待した結果、実際の結果、Redmine とプラグインのバージョン、ブラウザー、関係する権限、関連ログを添えて[GitHub Issues](https://github.com/tiohsa/redmine_canvas_gantt/issues)に報告してください。チケット番号、件名、ユーザー名、ホスト名、認証情報、API キー、機密ログを公開前に伏せてください。スクリーンショットは必要な範囲だけを切り出し、個人情報を隠します。
